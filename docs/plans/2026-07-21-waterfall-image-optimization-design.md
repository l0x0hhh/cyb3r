# 设备瀑布流与图片优化设计

> 状态：历史设计稿（2026-07-21）。本稿中的图片上限、瀑布流实现和卡片操作文案属于原方案；当前实现已改为单文件 20 MB 上限和按响应式列分配的独立列布局，现行规则以 `docs/PROJECT_GUIDE.md` 和源码为准。

## 目标

- 将 `/borrow` 的可借设备列表改为类似内容社区的响应式瀑布流：手机 2 列、平板 3 列、桌面 4 列。
- 保留 `/borrow?id=<deviceId>` 直接进入单设备详情的行为。
- 管理员上传图片时自动生成列表缩略图和详情图，减少扫码后等待时间。
- 兼容历史设备数据，旧记录只有 `image` 时仍可正常显示。

## 图片处理

本稿原方案：上传只允许 JPEG、PNG 和 WebP，最大 5 MB。通过文件签名校验后：

- 自动应用 EXIF 旋转。
- 生成最长边不超过 1280px、质量 80 的详情 WebP。
- 生成宽度不超过 480px、质量 72 的列表 WebP。
- 保存详情图宽高，供浏览器提前预留图片空间。
- 删除上传过程中的临时原图；生成文件使用随机名称，可安全设置长期不可变缓存。

新设备字段为 `image`、`imageThumb`、`imageWidth`、`imageHeight`。公共接口和管理员接口均返回兼容后的字段：历史数据的 `imageThumb` 回退为 `image`。

## 前端交互

- 本稿原方案：可借设备列表使用 CSS 多列布局，卡片禁止跨列断开。
- 列表使用 `imageThumb`，前两张图片优先加载，其余图片懒加载。
- 图片按服务端宽高设置 `aspect-ratio`，加载期间显示暖灰色骨架，完成后淡入。
- 本稿原方案：卡片包含设备名称、型号、位置和“查看详情”提示，整张卡片可点击。
- 单设备详情继续使用 `image`、`loading="eager"` 和高优先级加载。

## 兼容与验证

- 不覆盖服务器持久化目录中的旧图片，也不要求一次性迁移历史数据。
- 新上传或重新编辑图片的设备自动获得优化后的图片版本。
- 自动化验证覆盖图片变体、尺寸字段、缓存头、历史字段回退和瀑布流源码契约。
- 最终运行 `node --check server.js`、`npm test`、`npm run build`，并检查桌面与移动端页面。
