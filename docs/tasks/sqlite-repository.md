# SQLite 记录集合差异写入

## 已完成范围

- `db/repository.js` 仅优化记录集合；设备、分类、日志、管理员和邮件设置保持原实现。
- 每次写入仍接收完整数组，沿用原字段转换，读取当前事务内数据库行后比较；新增 ID 执行 INSERT，字段变化执行 UPDATE，缺失 ID 执行 DELETE。空数组删除全部记录；重复的转换后 ID 报错，不静默合并。
- 不保存跨调用缓存；同一事务连续写入、回滚后重试均以数据库当前行作为依据。
- 新增 `test/sqlite-repository.test.js`：只用内存 SQLite 和合成数据，替换依赖入口以避免业务数据库、首次迁移或磁盘数据库访问；运行完整仓储 SQL，临时触发器记录行 DML 并注入失败。

## 完整快照兼容

`createSqliteStore` 的 `databasePath`、`readCollection`、`writeCollection`、`transaction`、`close` 均保留，参数和同步返回方式不变。调用方不需要改用补丁、增量列表或定向查询。

字段仍先经原 `text` / `nullableText` / 布尔转换再比较。普通文本的缺失值仍转空字符串，可空文本的空字符串仍转 NULL；数据库中原本存储的可空字段空字符串，在下一次快照写入时仍按旧逻辑规范化为 NULL。`department` / `notes` 与 `major` / `purpose` 保留原适配，仓储没有新增互相补值；首次迁移旧字段兜底仍由原迁移逻辑处理。管理员权限、SMTP、收件人、邮件模板的 JSON 适配未改。

归档和归还字段仍是普通快照字段，不过滤归档行，不新增默认值或按日期排序。旧实现删除后按输入数组顺序插入，读取通常对应 rowid 顺序；新实现显式按 rowid 读记录，保留输入数组顺序：已有且仍递增的 rowid 保留，中间新记录或重排时将必要后缀移到原最大 rowid 之后。普通追加、删除、字段修改不因位置收缩重写其余行。rowid 仅供内部排序，不返回给业务方。

原 `BEGIN IMMEDIATE`、嵌套事务共用外层边界、异常 ROLLBACK、WAL、busy timeout、重复关闭行为未改。没有新增 savepoint；外层自行捕获嵌套异常时仍沿用原事务控制语义。重复 ID 现在在记录 DML 前显式拒绝，保留 `UNIQUE constraint failed: records.id` 文本，不承诺驱动错误对象附加属性一致。

## 预期写入变化（未实测）

以下是 SQL 路径推导的预期行操作数，不是磁盘页、WAL 字节数、耗时或吞吐测量。

| 完整快照场景 | 原路径 | 新路径预期 |
| --- | --- | --- |
| N 行完全无变化 | 全表删除再插入 N 行 | 0 行 DML；仍有全量读取、比较和事务开销 |
| 仅 1 行字段变化、顺序不变 | 全表删除再插入 N 行 | 1 行 UPDATE |
| 末尾追加 1 行 | 全表删除再插入 N+1 行 | 1 行 INSERT |
| 删除 1 行，其余相对顺序不变 | 全表删除再插入 N-1 行 | 1 行 DELETE |
| 混合增删改、顺序不变 | 全表删除并重插 | 仅删除缺失 ID、插入新增 ID、更新变化行 |
| 中间插入或重排 | 全表删除并按新顺序重插 | 差异操作，另更新维持顺序所需后缀；极端重排可能更新大量行 |
| 空集合 | 全表删除 | 按现存 ID 删除全部行；已经为空时 0 行 DML |

仍是 O(N) 全量读取与比较、O(N) 内存。预期减少无变化行写入与相关索引维护，没有实测，不宣称提升倍数。
