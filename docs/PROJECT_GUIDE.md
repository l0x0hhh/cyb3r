## 1. 项目目标

这是供学院内部使用的轻量设备借还系统：

- 管理员上架、编辑、上下线和删除设备，并管理借用记录。
- 普通用户扫描一个统一二维码，查看可借设备、填写信息借用或查询本人待归还设备。
- 系统部署在学院可访问的公网服务器上，使用域名 `cyb3r.art` 和 HTTPS（Let's Encrypt 证书），Nginx 已开启 HTTP/2。
- 数据使用本地 JSON 文件持久化，适合当前小规模内部使用场景。

## 2. 当前产品规则

### 统一入口

- 普通用户入口：`/borrow`
- 管理后台：`/admin`
- 微信小程序普通用户端：`miniprogram/`（AppID `wx46f682f7e11b893d`）
- 生产用户端：`https://cyb3r.art/borrow`
- 生产管理端：`https://cyb3r.art/admin`
- 根路径 `/` 重定向到 `/borrow`
- 统一二维码指向 `/borrow`
- 系统长期保留两套二维码：统一二维码用于查看全部可借设备；每台设备的独立二维码用于单独打印和粘贴
- 单设备二维码链接 `/borrow?id=<deviceId>` 直接打开统一门户所使用的同一个设备详情组件
- 用户端、管理后台、登录页、跳转页、页脚和浏览器标题统一标识“暨南大学网络空间安全学院”。
- 页面采用正式学院风与轻科技感结合的院徽青蓝配色；完整院徽以紧贴蓝色外圈的透明裁切版用于页面品牌区，不附加白色底板，中央盾牌裁切版用于 favicon。
- 用户端“借设备/还设备”导航与管理端顶部导航使用半透明米白毛玻璃吸顶层、细边框和轻阴影；导航激活态不使用蓝色滑动指示线。管理员图片选区只在高度提示信息牌上使用局部玻璃效果，预览原图不增加额外模糊。
- 青蓝色仅用于品牌与交互强调；可借、借出和离线状态继续分别使用绿色、红色和灰色表达。
- 用户端和管理后台底栏均显示“本站已运行 X 天 X 小时 X 分 X 秒”，基准时间为 `2026-07-21 12:00:00`；运行时长由浏览器本地计算，不依赖后端时钟。
- 用户端和管理后台底栏在学院名称与运行时长之间显示一条随机一言；每次页面装载仅请求一次诗词或哲学分类且最长 40 字的内容，正文链接到一言官方 UUID 详情页；请求超过 2.5 秒或失败时保留本地默认文案，不影响核心业务；一言使用站点统一无衬线字体 `14px`。
- 一言正文按 60ms/字逐字显示，完成后光标保留约 1 秒；组件卸载时清理定时器，`prefers-reduced-motion: reduce` 下直接显示完整文案并关闭光标动画。

### 借设备

- 公共列表只显示 `online + available` 的设备。
- 公共列表采用类似小红书的响应式瀑布流：手机 2 列、平板 3 列、桌面 4 列；卡片媒体区按照片宽高比例显示，缺少后端宽高字段的老图会在加载后读取浏览器 `naturalWidth/naturalHeight` 作为兜底；列表加载缩略图，前两张优先加载，其余图片懒加载。
- 图片媒体容器和无图占位固定使用 `#f0ece4` 主色；有图片但尚未完成加载时不显示 Skeleton、shimmer 或 spinner，图片保持 `opacity: 0`、`blur(15px)`、`scale(1.03)`，加载完成后过渡到 `opacity: 1`、`blur(0)`、`scale(1)`，opacity 过渡 0.3s，filter/transform 过渡 0.6s。
- “可借设备”右上角数量显示当前搜索和分类筛选后的设备量，切换筛选结果时使用短暂的数字过渡动画。
- 瀑布流卡片的信息区在设备位置元数据后自然结束，不保留透明的隐藏操作行占位，避免卡片底部产生额外留白；整张卡片链接仍可打开详情。
- 点击设备后显示图片、名称、型号、位置、说明和当前状态；详情媒体区宽度固定为容器宽度，若设备保存了展示高度则按该高度显示，图片使用 `object-fit: cover` 和保存的垂直 `object-position` 铺满；没有展示高度的旧设备继续按自然比例显示。
- 移动端打开设备详情时，瀑布流列表保持挂载，详情作为吸顶借还导航下方的独立固定滚动层进入；不得锁定根文档、平滑滚动整个文档、手动保存/恢复文档滚动位置或等待列表离场。详情首帧复用已加载卡片数据，再异步刷新设备状态；关闭详情不重新请求列表，列表内详情通过真实浏览器历史返回，直接链接详情则原地关闭并回到 `/borrow`。移动端进入保留短促的 `transform` 位移，返回不执行反向离场动画，仅以 `preventScroll` 恢复原设备焦点。详情外层从首帧保持不透明，避免底层分类标签透出；减少动态效果模式下关闭转场。
- 新上传或重新上传的设备图片单次最多接收 20 MB；管理员选图后进入截图工具式高度选区，外围变暗、中间选区高亮，右上角显示实时 `H: xxxpx`，选区主体支持上下拖动，底部 `↕` 手柄支持鼠标和触摸调整高度；服务端接收后由 Sharp 自动旋转、缩放并生成 WebP 详情图和缩略图，上传临时原图处理完成后不保留；只保存展示层的 `imageDisplayHeight` 和 `imageDisplayPositionY`（0-100%）。编辑已有设备时可以重新选择图片，旧图片继续兼容。
- 借用必填：姓名、11 位完整手机号、专业、用途。
- 学号/工号选填。
- 后端再次校验设备存在、在线且未借出，不能只依赖前端状态。

### 管理员邮件通知

- 管理员后台提供“邮件通知”Tab，可配置单个 SMTP 发件账号、端口、加密方式（SSL/TLS、STARTTLS 或无加密）、多个接收邮箱、借出/用户归还/管理员归还三类通知开关，以及主题和正文模板。
- 模板支持 `eventLabel`、`deviceName`、`deviceModel`、`deviceId`、`borrowerName`、`borrowerId`、`borrowerNameMasked`、`borrowerIdMasked`、`borrowerPhone`、`borrowerPhoneMasked`、`major`、`purpose`、`borrowedAt`、`eventAt`、`returnNotes`；未提交的模板字段在部分更新时沿用当前配置。
- 邮件设置默认开启 `maskSensitiveData`，模板中的姓名、学号/工号和手机号会按该开关统一脱敏；显式 `*Masked` 变量始终脱敏。管理员关闭脱敏属于明确的隐私风险选择。
- 借用记录或归还记录成功写入后才异步发送邮件；SMTP 发送失败只记录服务端日志，不回滚借用或归还结果。默认模板使用脱敏个人信息。
- SMTP 密码/授权码只在服务器使用 `EMAIL_CONFIG_KEY` 通过 AES-256-GCM 加密写入 `DATA_DIR/email-settings.json`，接口不回传原始凭据，前端只显示“凭据已保存”。
- 管理员可使用当前页面草稿和预览事件发送测试邮件；测试邮件只使用模拟借用记录，不读取真实借用人数据，也不持久化草稿。当前发送没有持久化重试队列，服务重启或进程异常时不会补发已失败通知。
- 管理员邮件页面提供中文字段按钮、主题/正文光标插入、借出/归还预览切换和实时示例邮件预览；模板错误会阻止保存和测试发送。移动端预览会移动到编辑器上方，便于先确认邮件效果。

### 微信小程序普通用户端

- 该方向当前按用户决定暂缓；本地 `miniprogram/` 目录保留，不纳入网页端本轮部署或后续迭代。
- 小程序第一版只提供普通用户借还流程，管理员继续使用网页端 `/admin`，不在小程序中复制管理员会话和上传能力。
- 小程序通过 `miniprogram/services/api.js` 请求 `https://cyb3r.art` 的公开接口：分类、可借设备、设备状态、借用、归还查询和归还确认。
- 小程序页面为设备列表/搜索/分类（`pages/borrow/index`）、详情（`pages/detail/index`）、借用表单（`pages/borrow-form/index`）和归还查询（`pages/return/index`）。
- 图片地址由 API 层统一补全，列表优先使用缩略图；媒体容器使用 `#f0ece4` 占位和模糊渐显，不使用 Skeleton、shimmer 或 spinner。
- 小程序不包含 AppSecret；上线前需要在微信公众平台配置 `https://cyb3r.art` 为 request 合法域名，并由用户在微信开发者工具和真机手动验证。
- 小程序的设备图片和院徽通过 `<image>` 从公网加载，因此微信公众平台还必须把 `https://cyb3r.art` 加入 downloadFile 合法域名；只配置 request 合法域名不足以保证图片显示。

### 还设备

- 用户输入借用时的完整手机号和姓名进行精确查询。
- 查询只返回该身份当前未归还的设备，不返回其他人的信息。
- 查询成功后签发有效期 10 分钟的短期归还凭证。
- 用户选择具体设备确认归还，可填写归还备注。
- 无匹配记录时显示“你当前没有待归还的设备”。
- 查询与归还接口均有限流。

### 设备状态

设备状态分为两个独立维度：

| 维度 | 值 | 含义 |
|---|---|---|
| 借用状态 `status` | `available` / `borrowed` | 是否正在借用 |
| 运营状态 `operationalStatus` | `online` / `offline` | 是否允许对外提供 |

规则：

- 只有已归还、当前为 `available` 的设备才允许下线。
- 借出中的设备前端禁用下线操作，后端也会返回 `409` 拒绝。
- 管理员点击下线时先确认设备名称；只有确认后才继续询问离线原因，取消确认不会弹出原因填写框。
- 离线设备不出现在公共列表中，也不能借用。
- 下线不会删除设备、图片、二维码或历史记录。
- 管理员可以填写离线原因，并在维修完成后重新上线。
- 历史设备没有 `operationalStatus` 字段时按 `online` 处理。

### 分类管理

- 管理员可以新增、重命名和删除分类；删除普通分类时，其设备自动迁移到 `cat-other`。
- 新增或编辑设备时必须选择有效分类；前端和后端都会拒绝空分类或未知分类。
- 分类管理列表使用紧凑拖拽排序，所有分类都参与排序；`cat-other` 仅不可删除，仍可拖动到任意位置。
- 分类图标和数字排序控件不再出现在管理界面；历史 `icon` 字段继续保留以兼容旧数据。

### 设备批量导入与导出

- 管理员可下载真实 `.xlsx` 模板，导入列依次为设备名称、设备型号、设备分类、存放位置、设备说明；前三列必填。模板包含下载时的现有“分类选项”工作表，设备分类列 2-501 行通过 Excel 数据验证下拉框选择当前分类名称；分类变化后应重新下载模板。
- 浏览器仅在管理员实际打开模板、导入或导出工作簿功能时动态加载 `exceljs@4.4.0`；普通用户首屏不加载 ExcelJS。加载后展示逐行预览；空白行忽略，表头必须完全匹配，单次最多 500 台，任何错误都会禁用提交。
- `POST /api/devices/batch-import` 受管理员保护并复验全部数据；分类名必须唯一匹配现有分类，任一行错误时零写入。重复名称和型号允许，每行创建一台默认在线、可借、无图片的设备。
- 成功导入只追加一条 `devices_batch_imported` 汇总操作日志。管理员可导出全部设备的 ID、名称、型号、分类、位置、说明、借用状态、运营状态和下线原因。
- 批量上线、批量下线和批量分类均已实现。批量分类可处理借出或下线设备，服务端先校验目标分类与全部设备，任一设备无效时整批零写入，成功后只追加一条 `devices_batch_categorized` 汇总日志。

### 隐私与管理员权限

- 管理员分为 `super_admin` 和 `admin` 两级。现有 `ADMIN_PASSWORD` 环境账号首次启动时迁移为用户名 `admin` 的超级管理员，可用 `ADMIN_USERNAME` 指定兼容账号名；旧的仅提交密码登录请求仍默认登录该账号。
- 管理员账户持久化在 `DATA_DIR/admin-users.json`，字段包含 `id`、`username`、`passwordHash`、`role`、`permissions`、`createdAt` 和 `updatedAt`；密码只保存 Node `crypto.scrypt` 哈希，不保存明文。该文件应保持仅服务用户可读，禁止提交真实账号数据。
- 超级管理员始终拥有全部功能，并可新增、删除普通管理员和更新其功能权限；普通管理员只能使用 `devices`、`records`、`categories`、`statistics`、`operation-logs`、`email-settings` 中被授权的功能。管理员管理接口只允许超级管理员调用，不能删除超级管理员。
- 管理员修改密码接口为 `PUT /api/admin/password`，必须提交正确原密码、新密码和确认新密码；新密码至少 8 位、两次输入一致且不能与原密码相同。
- 管理后台登录后按服务端返回的角色和权限过滤 Tab；前端隐藏入口不替代后端权限校验，未授权接口统一返回 403。
- 管理后台导航按“运营管理、配置管理、数据分析、系统设置”分组；桌面端使用可折叠侧栏并保存折叠偏好，移动端使用带遮罩的抽屉菜单。账户区只提供修改密码和退出，设备下载、导入、导出、统一二维码等低频操作收进“更多”菜单。

- 普通用户看到的姓名：两字显示“张*”，三字及以上保留首尾，如“张*龙”“欧**娜”。
- 普通用户看到的手机号只保留前三位，如 `138****`。
- 普通用户不能枚举完整借用记录。
- 管理员可以查看和修改完整借用信息、强制归还、归档、恢复和永久删除已归还记录。
- 管理员可以查看近 7 天、近 30 天或全部借用统计，包括借用次数、已归还、当前借出、设备使用率、热门设备前 5 名和按日趋势；归档记录仍计入历史统计，永久删除记录不再计入。
- 借用统计范围切换保留已有统计内容，概览数字使用前端动画平滑过渡，按日趋势柱从底部生长；首次加载仍显示加载状态，统计请求失败且已有旧数据时保留旧面板并提示错误。`prefers-reduced-motion: reduce` 下直接展示结果，不新增后端接口或第三方依赖。
- 借用统计趋势按返回日期数量使用连续 CSS Grid 列，列间距为 0，趋势柱填满各自列；统计面板标题和数字使用站点无衬线字体 `var(--sans)`，其他页面既有字体规则不变。
- 管理员可以查看设备新增、批量导入、批量分类、批量上线、批量下线、设备编辑、设备下线和管理员归还日志；只记录成功操作及设备元数据，不保存借用人姓名、手机号等隐私信息，失败或取消操作不写日志。
- 管理后台顶部可以生成统一二维码，每张设备卡片可以生成、打开或下载该设备的独立二维码。
- 管理后台设备区支持卡片和紧凑列表两种视图；设备卡片和列表均可勾选 1-500 台设备执行批量分类、批量上线或批量下线。批量分类允许处理借出和下线设备；批量下线统一填写原因，借出设备或无效设备会使整批拒绝且不写入；批量上线无需原因、允许处理借出设备并清空原下线原因。三种操作成功后分别只追加一条汇总日志。桌面端和移动端设备工具栏均区分普通状态与选择状态：选择设备后隐藏无关工具；桌面端直接显示批量分类、上线和下线，移动端直接显示“分类”并将上线/下线收进选择状态的“更多”菜单。移动端普通状态把下载、导入、导出和统一二维码收进“更多”菜单。两种视图提供相同的设备操作，视图偏好保存在当前浏览器，不写入服务端数据。Tab 按常用程度排列，“借用统计”和“操作日志”位于“分类管理”之后。
- 删除设备前必须二次确认；确认后可以级联删除该设备的全部借用记录。

## 3. 技术架构

```text
浏览器
  ├─ /borrow 统一借还门户
  └─ /admin  管理后台
        │
        ▼
Nginx :80 / :443
        │ 反向代理
        ▼
Express / Node.js :3000
  ├─ REST API
  ├─ Vue/Vite 生产静态文件
  ├─ JSON 数据文件
  ├─ 上传图片
  └─ 生成的二维码
```

主要技术：

- Node.js + Express 4
- Vue 3，当前使用运行时模板，未拆分为 `.vue` 单文件组件
- Vite 8 生产构建
- Helmet、express-rate-limit、Multer、Sharp、qrcode
- Nginx + systemd 生产部署

管理员账户文件由服务端在 `DATA_DIR` 初始化；不存在时从 `ADMIN_PASSWORD` 生成超级管理员。示例只用于说明字段，不得写入真实密码哈希或生产账号。

历史兼容：

- 旧设备只有 `image` 时，接口将 `imageThumb` 回退为 `image`；宽高缺失时前端使用默认比例。
- 旧设备没有 `category` 时读取为 `cat-other`；新建和编辑设备必须提交有效分类。
- 旧设备没有 `imageDisplayHeight` 时详情页按自然比例显示；新上传或编辑时可通过可视化拖拽选区保存 120-720px 的展示高度。
- 旧设备没有 `imageDisplayPositionY` 时详情页默认居中；新上传或编辑时通过拖动选区主体保存 0-100 的垂直位置百分比。
- 旧图片不会在部署更新时被覆盖或自动重写；可通过 `npm run migrate:images -- --dry-run` 预览，再通过 `npm run migrate:images` 补齐详情/缩略 WebP 并更新设备引用。迁移命令保留旧原图且可重复执行。
- 旧记录的 `department` 读取为 `major`。
- 旧记录的 `notes` 读取为 `purpose`。
- 新写入记录目前同时保留旧字段，方便旧部署脚本或历史前端读取。
- 已经产生乱码的旧 JSON 内容无法可靠自动恢复，需要管理员重新编辑或删除。

## 7. 安全与运行时行为

- 生产环境必须提供 `ADMIN_PASSWORD`，否则服务拒绝启动。
- 可选环境变量 `ADMIN_USERNAME` 用于指定兼容迁移账号名，默认值为 `admin`；新增管理员使用超级管理员界面的用户名和初始密码创建。
- 管理会话保存在 Node.js 内存中，有效期 8 小时；服务重启后需要重新登录。
- 管理员密码使用 Node `crypto.scrypt` 和随机盐哈希；修改密码必须验证原密码、确认两次新密码一致且新密码至少 8 位。
- 归还凭证保存在 Node.js 内存中，有效期 10 分钟；服务重启后需要重新查询。
- 邮件 SMTP 密码/授权码不回传前端，使用 `EMAIL_CONFIG_KEY` 作为 AES-256-GCM 密钥加密写入 `DATA_DIR/email-settings.json`；更换该环境变量会使既有密文无法解密，需要管理员重新录入凭据。
- 借出、用户归还和管理员归还通知在记录成功写入后异步发送；发送失败不影响业务结果，目前没有持久化重试队列。
- 登录、借用、归还查询和归还操作均有限流。
- 上传仅允许 JPEG、PNG 和 WebP，单次最多 20 MB，并检查文件签名；不允许 SVG。前端不改写原图，校验通过后由 Sharp 自动旋转、缩放并按原比例生成详情与缩略 WebP，展示层高度由 `imageDisplayHeight` 控制，临时原图不会保留。旧图迁移命令只新增 WebP 变体，不删除原图。
- 随机命名的上传图片使用一年 `immutable` 浏览器缓存；更换图片会产生新地址，不会命中旧图片缓存。
- HTTPS 已启用 HSTS（`max-age=31536000; includeSubDomains`）和 `upgrade-insecure-requests`；前端脚本不会回退到 HTTP。
- 当前 Vue 运行时模板需要 CSP `unsafe-eval`；迁移到预编译 `.vue` 组件后可移除。
- Google Fonts CSS 由 `https://fonts.googleapis.com` 提供，字体文件由 `https://fonts.gstatic.com` 提供；两者分别在 CSP 的 `style-src`/`style-src-elem` 与 `font-src` 中显式放行。
- 网页底栏仅通过 CSP `connect-src` 放行 `https://v1.hitokoto.cn`；请求不携带借用人、设备或管理员数据，每次页面装载最多主动请求一次。

首次部署优先参考 `deploy/setup-server.sh`。生产源码接入 GitHub 后，日常更新使用 `deploy/update-from-git.sh`：服务器以 `deviceapp` 通过只读 Deploy Key 执行快进拉取，只有依赖、前端或后端确实变化时才安装依赖、构建或重启；所有 Git、npm 和 Node 命令都会先切换到 `/opt/device-management`，避免继承 SSH 调用者的当前目录；如果本次拉取包含更新脚本，当前进程会自动用仓库中的新版本继续执行。脚本还会在提交已是最新时检查 `frontend/dist/index.html` 是否缺失或早于 `frontend/src`、入口和 Vite 配置，支持上次构建中断后的再次运行自动恢复。脚本会在 npm 操作前运行 `namei -l` 和 `sudo -u deviceapp test -r`，工作区不干净、远端不是快进或远端提交跟踪受保护路径时直接停止。手动增量上传仍必须先使用 `skills/sync-device-management/SKILL.md` 分类实际改动；PowerShell `scp -r` 上传的暂存目录可能属于 `ubuntu:ubuntu` 且权限为 `0700`，严禁使用 `sudo cp -a <stage>/. /opt/device-management/` 将暂存目录元数据复制到应用树；必须对每个变更文件执行 `sudo install -D -o deviceapp -g deviceapp -m 0644 <staged-file> <target-file>`，可执行脚本才使用 `0755`。自动化测试优先在本地运行；生产服务占用 3000 端口时不要直接运行集成测试。任何更新都必须保留 `/var/lib/device-management`，禁止上传本地 `data/`、`uploads/` 和 `public/qrcodes/` 覆盖生产数据。
